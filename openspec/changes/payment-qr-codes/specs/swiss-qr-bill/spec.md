# Spec Delta — swiss-qr-bill

## Purpose

Decode, validate, and encode the Swiss QR Code payload of a QR-bill (SIX Implementation Guidelines QR-bill v2.3, valid from 21 November 2025; v2.4 valid from 14 November 2026), entirely in the browser.

## ADDED Requirements

### Requirement: Payload decoding
The tool SHALL parse a Swiss QR Code payload (LF or CRLF separated) in the SIX IG v2.3 §4 element order and SHALL render each populated element with its IG label. The element groups are: header; creditor information; creditor address; ultimate-creditor placeholders; payment amount information; ultimate debtor address; payment reference; additional information; alternative schemes.

#### Scenario: Element groups are labelled
- **WHEN** a conformant payload is decoded
- **THEN** the result groups rows under Header (`SPC` / `0200` / `1`), Creditor (IBAN kind, address type, name, street, building number, postal code, town, country), Amount (amount, currency), Ultimate debtor, Payment reference (type `QRR` / `SCOR` / `NON`, reference), Additional information (message, `EPD` trailer, billing information), and Alternative schemes (up to two lines)

#### Scenario: SIX sample bill decodes
- **WHEN** the user pastes a payload with `SPC` / `0200` / `1` / `CH4431999123000889012` / structured creditor address `S` `Max Muster & Söhne` `Musterstrasse` `123` `8000` `Seestadt` `CH` / amount `1949.75` `CHF` / structured debtor / `QRR` / `210000000003139471430009017` / `Order from 15.10.2020` / `EPD`
- **THEN** the result shows the QR-IBAN (IID 31999 is in the 30000–31999 QR-IID range), the creditor address lines, CHF 1 949.75 formatted per the active locale, reference type QRR with the reference grouped `21 00000 00003 13947 14300 09017`, and every gate row ✓

#### Scenario: Image round trip through the page's QR decoder
- **WHEN** a QR-bill image generated by the encode panel (including the Swiss cross overlay) is loaded in the decode panel
- **THEN** the payload decodes to the same table, demonstrating that level-M error correction absorbs the overlaid centre modules

### Requirement: Account and reference gates
The tool SHALL display independent ✓ / ✗ rows for: header is `SPC` / `0200` / `1`; IBAN is a CH or LI IBAN passing MOD-97; reference type matches the IBAN kind (QR-IBAN, IID 30000–31999, requires `QRR`; an ordinary IBAN requires `SCOR` or `NON`); a `QRR` reference is 27 digits with a valid modulo-10-recursive check digit; a `SCOR` reference is valid per ISO 11649; `NON` carries an empty reference.

#### Scenario: QRR check digit failure
- **WHEN** the reference type is `QRR` and the reference is `210000000003139471430009018`
- **THEN** the reference gate is ✗ and names the modulo-10-recursive check (expected check digit 7)

#### Scenario: Ordinary IBAN with QRR reference
- **WHEN** the IBAN's IID (positions 5–9) is outside 30000–31999 and the reference type is `QRR`
- **THEN** a ✗ gate row states that QRR references require a QR-IBAN

### Requirement: Amount and currency gates
The tool SHALL display independent ✓ / ✗ rows for: amount (when present) with exactly two decimals within 0.01–999999999.99, compared in integer cents; currency `CHF` or `EUR` (SIX IG v2.3 §4, "Payment amount information").

#### Scenario: Three-decimal amount
- **WHEN** the amount element is `1949.750`
- **THEN** the amount gate is ✗ citing the IG's two-decimal rule

### Requirement: Address and size gates
The tool SHALL display independent ✓ / ✗ rows for: creditor address type `S`, with type `K` as a dated gate (⚠ before 14 November 2026, ✗ from that date, SIX IG v2.4); mandatory address fields present within the IG caps (name 70, street 70, building number 16, postal code 16, town 35, country 2); `EPD` trailer present; message plus billing information ≤ 140 characters; payload ≤ 997 characters; ultimate-creditor block empty (IG v2.3 §4, reserved).

#### Scenario: Combined address after the v2.4 cutover
- **WHEN** the creditor address type is `K` and the browser date is on or after 14 November 2026
- **THEN** the address-type gate is ✗ citing SIX IG v2.4; before that date it is a ⚠ warning citing IG v2.3 deprecation

### Requirement: Payload encoding
The tool SHALL provide a form (creditor IBAN, structured creditor address, optional amount and currency, optional structured debtor address, reference type and reference, optional message and billing information) that serialises a conformant payload, runs the same gates, and renders the Swiss QR Code at error-correction level M with the 7 mm Swiss cross overlaid, offering the payload text and a PNG download annotated with the 46 × 46 mm print-size hint.

#### Scenario: Encoder emits structured addresses only
- **WHEN** the user completes the encode form
- **THEN** the serialised address type is always `S` (the encoder offers no combined-address mode)

#### Scenario: Encoder refuses an inconsistent reference
- **WHEN** the IBAN is a QR-IBAN and the reference type selected is `NON`
- **THEN** no QR is rendered and the reference gate ✗ explains the QR-IBAN / QRR pairing

### Requirement: Offline operation and verdict language
The tool SHALL perform all decoding, validation, and rendering without any network request, and SHALL phrase an all-✓ result as conformance to the named IG version, never as the payee or payment being safe or verified.

#### Scenario: No network, conservative wording
- **WHEN** every gate is ✓
- **THEN** the summary reads "Conforms to SIX QR-bill IG v2.3 — this does not verify who the creditor is", and the network log shows no request
